# 작업수행 규칙

## 계획·실행·검증

1. wiki-desk로 같은 모델·아키텍처·실패의 근거를 찾아 원문을 읽고 계획에 연결한다. 기록이 없으면 그렇게 적고 진행한다.
2. 승인된 Seed·plan을 구현한다. 이미 승인된 작업을 위상마다 재승인받지 않는다. 모델별 장치·입력 길이·출력 차원은 실제 실행 전에 HITL로 확정한다.
3. 시도·변경·근거·결과·재개 조건을 devlog에 남기고, 실제 수행한 검증만 checklist에 체크한다. 발행 문서는 wiki-desk로 입고한다.
4. 변경에 맞는 검증과 코드 리뷰를 수행한다. Codex의 사용 가능한 리뷰를 사용하며 특정 외부 리뷰 플러그인을 필수 의존으로 두지 않는다. 검증된 소스 변경을 작업 단위로 커밋한다.

반복 실행 권한은 [Codex 실행 승인 관리](codex-permissions.md)를 따른다. 검증은 `python3 tools/verify.py`로 실행해 리다이렉션·glob 변형마다 승인 요청이 생기는 것을 줄인다. 영구 허용 규칙과 실제 사용자 승인 범위를 재사용한다.

최신 사용자 승인과 Seed의 계약이 과거 문서의 대체된 제한보다 우선한다. 승인된 스킬 복원을 과거의 동일 실패 2회 조건으로 보류하지 않는다. 상시 지침·추상화는 실제 의사결정에 필요한 만큼 유지한다.

## 근거와 상태

- 실제 관측·추정·테스트 데이터를 `measured`·`estimated`·`mock` 등으로 구분하고 출처를 남긴다. 정적 모델 판정은 현재 서빙 성공·영구적인 미지원 판정이 아니다.
- manifest는 관측 HW의 정본이다. 모델 프로필·승인 전략·시도·실효 설정·결과·산출물을 서로 연결한다.
- 모델과 환경의 적용 조건을 비교한 뒤 과거 경험을 재사용한다. 호환 후보 중 최근 **서빙 E2E PASS**를 출발점으로 사용해도 현재 실행은 다시 검증한다.
- 모델별 PASS/FAIL/BLOCKED/미검증과 전체 수행 완료를 구분한다. 실패를 PASS로 바꾸거나 대상을 말없이 생략하지 않는다.
- 모킹은 외부 의존을 격리하는 테스트에 사용하고 실측 산출물과 섞지 않는다. 폴백은 이유와 실제 선택을 기록한다. 파생 가능한 값을 중복 상수로 관리하지 않는다.

## 빌드·실패·재개

장시간·다중 조건 E2E는 [캠페인 규약](../campaigns/README.md)을 따른다. 새 세션/워커는 기존 캠페인의 status에서 목표·승인·미결 질문·현재 셀/attempt·실행 소유권을 읽고 step/run으로 진행한다. 호출 종료는 작업 완료가 아니다. 살아 있는 실제 명령/컨테이너를 대조하고 완료 셀을 중복 실행하지 않는다. 미응답 HITL은 안정적인 ID·범위·재개점을 보존해 input-required로 반환한다.

서빙 전략 승인 후 Codex가 빌드, 크래시/실패 분석, 근거 기반 조건·패치 조정, 재시도와 재개를 수행한다. 장치·입력 길이·차원의 변경이 필요할 때 HITL로 돌아간다.

- 무거운 작업 전에 시도 ID·환경·입력·명령·로그 위치를 기록한다. 현재 HW와 작업에 맞는 자원·시간/무진전 관측 조건을 정하고 근거를 남긴다.
- 새 시도에는 직전 실패, 확인할 가설과 변경점을 연결한다. 같은 실패를 근거 없는 동일 조건으로 반복하지 않는다.
- 중단 후 기록과 실제 프로세스·컨테이너·이미지·산출물을 대조한다. 부분 산출물을 완료로 집계하지 않고 사용자 변경을 덮어쓰지 않는다.
- 승인 전략 안에서 새로 시험할 근거 있는 조정이 없거나 기록한 실행 한계에 도달하면 해당 모델의 미해결 근거·기시도·재현/재개 조건을 남기고 다음 대상을 진행한다.
- WSL 크래시 경험은 이 호스트의 근거로 보존한다. 다른 환경에 Windows 술어·고정 GPU·수치·사람 직접 실행을 일괄 강제하지 않는다.

정리는 이 프로젝트가 만든 대상으로 한정한다. 사용자 자산·다른 프로젝트 이미지/볼륨·빌드 캐시를 전역 prune으로 지우지 않는다. 권한 밖의 호스트 설정 변경이나 비가역적인 조치는 실제 대상과 복구 경로를 확인한 뒤 필요한 승인을 받는다.

## 소스와 생성물

- 빌드 원천·템플릿·도구·규칙·스킬은 Git으로 관리한다. 생성 Dockerfile·이미지 참조·3+1+1·시도/검증 이력은 `output/`에 두고 추적하지 않는다.
- 빌드 산출물/패치는 upstream, 서빙 트리플렛/런타임 패치는 explorer, 루틴/검증 판정은 경량검증 스킬이 소유한다.
- Git 추적 파일은 이력을 권위로 삼고 `.bak`·backup 폴더·중복 digest로 권위를 늘리지 않는다. 재생성할 수 없는 실측·실패 근거는 보존한다.
- 미해결 과제는 문서 원문·output·위키를 연결해 새 대화 세션이 무엇을 시도했고 무엇을 더 확인해야 하는지 찾을 수 있게 한다.
