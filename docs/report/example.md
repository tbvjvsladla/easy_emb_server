# report — 공개 결과 보고서

배포자가 읽는 주제별 최신 보고서를 `docs/report/<topic-slug>.md`에 작성한다. 이 골격과 실제 Markdown 보고서를 Git으로 추적한다. easy-vllm-simulator의 공개 보고서 채널을 임베딩 단일 노드 검증에 맞춰 사용한다. 규약 정본은 [문서 규칙](../../rules/docs.md)이다.

## 권장 구성

1. 결과 요약: 처리 완료와 모델별 PASS/FAIL/BLOCKED를 구분한다.
2. 범위와 환경: 날짜·소스 커밋·HW 사양·모델/엔진/실효 설정·측정 조건.
3. 결과 표: 승인 장치·입력 상한·차원·기능검사·유효 측정·판정.
4. 실패와 복구: 관측한 원인·변경·재시도 결과. 초기 실패를 성공 이력으로 지우지 않는다.
5. 미해결과 재개 조건, 적용 한계, 근거 경로.

수치는 실제 결과에서 옮기고 단위·요청 수·동시성·출처를 적는다. 경량 측정을 정확도나 장시간 처리량 보장으로 표현하지 않는다. 모델별 현재 시도의 기능검사와 유효 측정이 함께 통과해야 PASS다.

계정·호스트명·IP·NAS 실경로·인증정보를 포함하지 않는다. 원시 로그/승인 영수증/체크포인트는 비추적 `output/`에 보존한다. 상대 근거 경로는 로컬 검토용이며 클론에 원본이 없음을 표시한다. 보고서의 결과 표는 본문만으로 읽을 수 있게 한다.

이 공개 채널은 wiki-desk 내부 작업 이력 색인 대상이 아니다. 발행 작업의 plan/devlog/checklist를 입고해 보고서와 검증 근거를 연결한다.
