# 로컬 서고 동시성 규정

> 정본 코드는 `src/concurrency.ts`(잠금·저널)와 `src/fs-safety.ts`(트랜잭션)다. 시험은 `tests/concurrency.test.ts`다.

## 무엇을 보호하는가

서고는 이 호스트의 로컬 디렉터리 하나다. 그래도 여러 프로세스(병렬 에이전트·사람의 손 실행)가 같은 서고에 동시에 닿을 수 있다.

| 축 | 불변조건 |
|---|---|
| 안전성 | 원문 하나에 카드는 정확히 하나다. `receipt.json`은 실제 카드 바이트의 해시 집합과 같다(유실·중복 0). |
| 원자성 | 어떤 순간에 읽어도 직전 커밋 상태이거나 다음 커밋 상태다. 중간 상태는 관측되지 않는다. |
| 진행성 | 쓰다 죽은 writer가 서고를 영구히 막지 않는다. 남는 잠금과 임시파일 잔재는 0이다. |

## 상호배제 — 커널 `flock(1)`

- 잠금 파일은 `<wiki>/.lock`이다. 쓰기(`sync --apply`)는 배타 잠금, 읽기(query·read·tree·check·status·`sync` 계획)는 공유 잠금을 쓴다.
- 잠금 보유자는 자식 프로세스다. 그 프로세스가 죽으면 커널이 잠금을 푼다 — 남는 잠금(stale lock)이 구조적으로 없다. lease가 아니므로 fencing token도 필요 없다.
- 대기 상한은 120초이고, 넘으면 fail-loud로 끝난다. `flock(1)`(util-linux)이 없으면 무잠금으로 대체하지 않고 거부한다.
- 트랜잭션의 preimage 재검증(계획 이후 경합 변경을 거부)은 잠금을 우회한 쓰기의 탐지기로 남긴다.

## 원자성 — 저널(write-ahead 의도 기록)

파일 단위 원자 교체(tmp → fsync → rename)만으로는 여러 파일을 쓰다 kill되면 중간 상태가 남는다. 그래서 다음을 덧붙인다.

1. 배타 잠금을 잡은 뒤 변경 직전에 `<wiki>/.journal/txn.json`을 fsync로 남긴다. 대상 파일 전부의 원본 바이트(없던 파일은 `missing`)와 새로 만들 디렉터리가 담긴다.
2. 파일별로 원자 교체한다.
3. 끝나면 저널과 빈 저널 디렉터리를 지운다. 예외가 나서 프로세스 안 롤백이 완전히 끝난 경우에도 지운다. 롤백이 불완전하면 저널을 남긴다.
4. **다음에 배타 잠금을 잡는 쪽**은 저널이 남아 있으면 원본으로 되돌리고, 원자 쓰기 임시파일(`.wiki-desk-txn-*`) 잔재도 지운다. 무엇을 되돌렸는지는 출력의 `journal_recovered`에 싣는다(침묵 복구 ✗).
5. 공유 잠금으로 읽던 쪽이 남은 저널을 만나면 읽지 않고 종료코드 75로 끝난다. 래퍼가 배타 잠금으로 승격해 복구한 뒤 같은 읽기를 다시 한다 — **읽기는 중간 상태를 볼 수 없다.**

## 실패 순서 시험

| 순서 | 시험 | 기대 |
|---|---|---|
| 동시 경쟁 | 여러 프로세스가 동시에 `sync --apply`·`query` | 카드 수 = 원문 수, receipt 해시가 카드 바이트와 일치, index에 전 카드가 실린다 |
| 부작용 직후 crash | n번째 변경 뒤 SIGKILL(`WIKI_DESK_FAULT_KILL_AT` · 시험 전용) | 다음 읽기가 복구 후에 읽는다, 직전 커밋과 바이트 동일, 잔재 0, 다음 입고 즉시 성공 |

시험은 별도 CLI 프로세스와 실제 `flock(1)`으로 돈다 — 한 프로세스 안에서 잠금이 성공하는 것으로 대체하지 않는다.

## 운영 파일

| 경로 | 성격 | receipt |
|---|---|---|
| `<wiki>/.lock` | flock 대상(내용 없음 · 상주) | 밖 |
| `<wiki>/.journal/txn.json` | 쓰기 중에만 존재 | 밖 |

둘 다 `.md`가 아니므로 OKF concept 분모에 들어가지 않는다. `check`는 저널 디렉터리를 건너뛴다.
